fastapi属于后端，专门给前端提供数据和接口
用户在前端操作，前端通过网络访问你用fastapi写的接口，
然后通过这个接口就可以去后端运行代码，运行结果通过接口返还给前端
同时fast API也是一整个后端框架，后端内容也是写在fast API里面的

是python生态钟最快，最现代化的web框架，专为构建高性能API而生，
结合了极致性能、开发效率、类型安全，是AI模型部署、微服务和高并发后端的首选工具。

最重要的：fastapi是一个web框架，你写了一段代码，只能自己运行，
要让别人也能用网页、小程序、APP、链接等访问这段代码，就需要一个接口。

和fast API一样能够生成一个接口让别人访问的还有
flask：老牌、轻量级，但是速度慢，基本上被fast API代替了
Django：全能型重型框架，适合用在大项目知乎淘宝这种


Docker 是一个用来打包、分发、运行应用的容器工具，
让你的代码在哪都能一模一样跑起来，不会出现 “我电脑上好好的，服务器上就崩了” 的问题。
也就是说docker像一个集装箱，把代码、python、依赖库、配置都装进去，跑到任何服务器都能直接跑
但是这个docker主要是给开发者、部署人员用的而不是给用户用的


pyproject.toml是声明依赖，uv.lock是实际装了什么，锁定版本
pyproject.toml是现代python项目的总配置文件，
作用是声明需要什么大方向的包，不写死精确版本
uv.lock是自动生成、精确锁定所有包版本的锁定文件。
uv.lock是给机器看的，pyproject.toml是给人看的，如果只有lock就没办法升级依赖，
但是有pyproject，就会自动给出最新版本然后升级依赖，修改并维护lock
还有一个问题就是子依赖问题，pyproject.toml只声明主依赖，lock要涉及所有子依赖

作为对比，requirement虽然可以写依赖，但是不写子依赖，所以子依赖不一样也会导致依赖包不一样。
而且lock会自动维护升级，同时lock更安全：哈希校验（随机生成的一个码，像指纹一样）


docker用容器化技术，给应用程序封装独立的运行环境，每个运行环境就是一个容器，运行容器的计算机被称为宿主机
docker和虚拟机最大的区别是：每个虚拟机都包含一个操作系统的完整内核，但docker容器之间共用同一个系统内核，所以比虚拟机更轻更小
镜像是容器的模板，可以把镜像类比成软件安装包，容器是安装出来的软件。docker镜像就像是模具，容器就像是用模具做出来的糕点
可以用模具做出来很多一样的东西，同时也可以把模具分享给其他人使用，镜像仓库就是用来存放容器的地方


Client（docker-cli）
Docker 用户交互入口，通过命令行发送指令（pull/run/build/push），负责将命令转发给 Docker 守护进程。
Docker Host（Docker 主机）
核心执行环境，以 Docker Daemon 为中枢，管理本地的镜像（Images）和容器（Containers），完成镜像的存储、容器的创建与运行。
Registry（应用市场）
镜像存储与分发中心，用于公共或私有共享镜像，支持 Docker Daemon 拉取（pull）和推送（push）镜像。
完整工作流
拉取运行流程
Client 执行docker pull → Docker Daemon 从 Registry 拉取镜像并存储到本地 → Client 执行docker run → Daemon 基于本地镜像启动容器。
构建推送流程
Client 执行docker build → Daemon 基于配置构建本地镜像 → Client 执行docker push → Daemon 将本地镜像上传到 Registry，实现共享。

传统部署，应用之间不隔离，会相互挤占
虚拟化部署：分割成不同的虚拟机，这样的话单个虚拟机炸了不会影响到别的虚拟机，有了隔离机制，但是每个虚拟机都有各自的操作系统
这样就很笨重
所以用容器部署：不同的容器用相同的操作系统，更轻便
