pyproject.toml是声明依赖，uv.lock是实际装了什么，锁定版本
pyproject.toml是现代python项目的总配置文件，
作用是声明需要什么大方向的包，不写死精确版本
uv.lock是自动生成、精确锁定所有包版本的锁定文件。
uv.lock是给机器看的，pyproject.toml是给人看的，如果只有lock就没办法升级依赖，
但是有pyproject，就会自动给出最新版本然后升级依赖，修改并维护lock
还有一个问题就是子依赖问题，pyproject.toml只声明主依赖，lock要涉及所有子依赖

作为对比，requirement虽然可以写依赖，但是不写子依赖，所以子依赖不一样也会导致依赖包不一样。
而且lock会自动维护升级，同时lock更安全：哈希校验（随机生成的一个码，像指纹一样）

## 学习清单（按优先级）

### 1) 全局认知（先建立地图）
- 看 `README.md`：确认 7 周目标与模块边界。
- 画一张你自己的数据流图：
  - `arXiv -> PDF解析 -> Postgres -> Chunk -> Embedding -> OpenSearch -> RAG -> Cache -> Agentic`
- 目标：你能口述“一个请求怎么走完整链路”。

### 2) 配置与依赖注入（所有代码入口）
- `src/config.py`
- `src/dependencies.py`
- 目标：搞清楚 `.env` 的变量最终如何进入服务对象。

### 3) 应用启动与生命周期
- `src/main.py`
- 看 startup/shutdown 初始化了哪些 client/service（DB、OpenSearch、Ollama、Cache、Langfuse、Telegram）。
- 目标：知道“服务为什么能在 router 里直接用”。

### 4) 数据层与模型
- `src/db/*`、`src/models/paper.py`
- 关注 `papers` 表字段：`raw_text`、`sections`、索引相关字段。
- 目标：理解“什么数据进入检索系统”。

### 5) ingestion 主链路（离线管道）
- `airflow/dags/arxiv_paper_ingestion.py`
- `airflow/dags/arxiv_ingestion/*`
- `src/services/arxiv/client.py`
- `src/services/pdf_parser/parser.py`
- 目标：讲清楚 DAG 每个 task 的输入输出与失败模式。

### 6) OpenSearch 与检索
- `src/services/opensearch/client.py`
- `src/services/opensearch/factory.py`
- 目标：理解 BM25、向量检索、混合检索调用路径和返回结构。

### 7) Embedding 层
- `src/services/embeddings/jina_client.py`
- `src/services/embeddings/factory.py`
- 目标：知道 query/document embedding 分别在什么时候调用，失败如何降级。

### 8) RAG API（核心在线路径）
- `src/routers/ask.py`
- `src/services/ollama/client.py`
- `src/services/ollama/prompts.py`
- 目标：完整走一遍 `/ask`：检索、拼提示词、生成、sources、异常处理。

### 9) 缓存与性能（Week6）
- `src/services/cache/client.py`（或同目录相关模块）
- `src/routers/ask.py` 里的 cache hit/miss 分支
- 目标：解释“为什么第二次查询快很多”。

### 10) Agentic RAG（Week7）
- `src/services/agents/agentic_rag.py`
- `src/services/agents/nodes/*`
- `src/services/agents/factory.py`
- 目标：理解 guardrail / retrieve / grade / rewrite / generate 的状态机跳转。

### 11) 可观测性（Langfuse）
- `src/services/langfuse/client.py`
- `src/services/langfuse/tracer.py`
- 目标：知道 tracing 是“增强功能”，不能影响主链路（我们这次就修过这点）。

### 12) Telegram（可选）
- `src/services/telegram/*`
- 目标：了解它只是一个入口层，复用现有 RAG 服务，不是核心引擎。

## 你的学习方法（强烈推荐）

每读完一个模块，固定回答 4 个问题（写在同一个文档）：

- 它的输入是什么？
- 它的输出是什么？
- 失败时会怎样降级？
- 它依赖谁、被谁调用？

这样你一周后会得到一份你自己的“项目内核文档”。
